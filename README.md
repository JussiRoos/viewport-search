# Viewport Search

A Chrome extension that finds a word on the page, highlights every match, and jumps from one **viewport** of matches to the next, skipping everything already on screen, instead of stepping match by match.

<img src="src/icons/icon-128.png" width="64" alt="">

## Features

- Highlights all matches (yellow) and the ones currently in view (orange) using the CSS Custom Highlight API, so the page DOM is not modified
- **Next / Prev** jumps to the next screenful of matches
- Match modes: substring, word prefix, or whole word, with Unicode-aware word boundaries (ä, ö, å, …)
- Status line: total matches and how many are in view

## Shortcuts

| Keys | Action |
|---|---|
| Alt+Shift+F | Open the search popup |
| Alt+Shift+N | Next viewport of matches |
| Alt+Shift+P | Previous viewport of matches |

Change them at `chrome://extensions/shortcuts`.

## Install for development

1. Open `chrome://extensions` and enable **Developer mode**
2. **Load unpacked** → select the `src/` folder
3. Reload any open tabs (content scripts only inject into pages loaded after install)

## Release

Pushing a tag builds a zip and attaches it to a GitHub release (see [.github/workflows/build.yml](.github/workflows/build.yml)):

```sh
# bump "version" in src/manifest.json first
git tag v1.0.1 && git push --tags
```

If the `CWS_EXTENSION_ID` repository variable and the `CWS_CLIENT_ID`, `CWS_CLIENT_SECRET` and `CWS_REFRESH_TOKEN` secrets are set, the same tag also uploads and publishes the build to the Chrome Web Store.

Icons are generated by `python3 scripts/make_icons.py` (requires Pillow).

## Limitations

- Only the top frame is searched
- Does not run on `chrome://` pages, the Chrome Web Store, or the built-in PDF viewer
- Highlights can go stale if the page re-renders; search again to refresh

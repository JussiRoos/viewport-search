# Viewport Search (Chrome extension)

Manifest V3 extension that finds a word on the current page, highlights all matches, and lets the user jump from one *viewport* of matches to the next (skipping every match already on screen), not match by match.

## Files

Extension source lives in `src/` (that folder is what gets zipped and loaded unpacked).

| File | Role |
|---|---|
| `manifest.json` | MV3 manifest: `activeTab` + `scripting` permissions (no static content script, no host permissions, to avoid the Web Store's broad-host-permission review), popup, background worker, keyboard commands |
| `content.js` | `ViewportSearch` class + `chrome.runtime.onMessage` listener (`search`, `next`, `prev`, `clear`, `state`) |
| `content.css` | `::highlight(vs-all)` yellow, `::highlight(vs-view)` orange (matches currently in view) |
| `popup.html` / `popup.js` | Injects `content.js`/`content.css` via `chrome.scripting` the first time a message to the tab fails; search input, match-mode select, Prev/Next/Clear, status line ("N matches · M in view") |
| `background.js` | Forwards keyboard shortcuts to the active tab's content script (no-op if the popup hasn't injected it yet) |
| `icons/` | 16/32/48/128 PNGs, generated by `scripts/make_icons.py` (Pillow); 128 has 16px transparent padding per Web Store guidelines |
| `.github/workflows/build.yml` | (repo root) Syntax-checks, zips `src/`; on `v*` tags creates a GitHub release and, if `CWS_EXTENSION_ID` var + `CWS_CLIENT_ID`/`CWS_CLIENT_SECRET`/`CWS_REFRESH_TOKEN` secrets are set, publishes to the Chrome Web Store. Tag must match manifest `version`. |

Shortcuts: Alt+Shift+N (next), Alt+Shift+P (prev), Alt+Shift+F (open popup).

## How it works

- `search(word, mode)` walks text nodes with a `TreeWalker` (skipping `script, style, noscript, textarea`), builds a `Range` per regex match, and highlights via the CSS Custom Highlight API (no DOM mutation).
- `_measure()` calls `getBoundingClientRect()` on each range, drops zero-size rects (e.g. `display: none`), sorts by on-screen position (top, then left), and flags `inView` (any overlap with the viewport, using `visualViewport` when available).
- `next()`: first match with `rect.top >= viewportHeight`; wraps to the first match. Scrolls so it sits `margin` px (80) below the top edge.
- `prev()`: last match with `rect.bottom <= 0`; wraps to the last. Scrolls so it sits near the bottom edge.
- If the target is inside an `overflow: auto/scroll` container, it uses `scrollIntoView` instead of `window.scrollTo`.
- Highlights repaint on scroll/resize via `requestAnimationFrame`.
- Message responses are delayed 450 ms after `next`/`prev` so the status line reflects the post-scroll "in view" count.

## Match modes

Set via the popup select, passed as `msg.mode`, remembered in popup `localStorage`:

- `partial` (default): substring anywhere (`cable` matches `cables`, `applicable`)
- `prefix`: word starts with the query (`cable` matches `cables`, not `applicable`)
- `word`: whole word only

Boundaries use Unicode lookarounds (`(?<![\p{L}\p{N}])`, `(?![\p{L}\p{N}])`) with the `u` flag, not `\b`, so letters like ä, ö, å count as word characters. The user is Finnish-speaking, so keep this working. The query is regex-escaped; do not escape `-` (invalid under the `u` flag).

## Known limitations / ideas

- Only the top frame is searched (`all_frames` is not enabled; enabling it would make each frame scroll and count separately).
- Ranges go stale if the page re-renders (SPAs, infinite scroll). Idea: debounced `MutationObserver` that re-runs `search(finder.word, finder.mode)`.
- "In view" means any overlap, so partially visible matches are skipped by `next()`. A full-containment variant is possible.
- `_measure()` runs on every scroll frame; with tens of thousands of matches, cache absolute positions after `search()` and only recompute on resize.
- Irregular forms (mouse/mice) would need stemming or fuzzy matching.
- Does not run on `chrome://` pages, the Web Store, or the built-in PDF viewer.

## Testing

No automated tests. The code has only been syntax-checked (`node --check`) and the three regex modes sanity-tested in Node; it has **not** been run in Chrome yet. To test manually: `chrome://extensions` → Developer mode → Load unpacked → select the `src/` folder. After editing, click the extension's reload icon.
